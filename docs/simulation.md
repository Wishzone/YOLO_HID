# HID 与预判调参仿真

仿真复用实际应用的 `AimController`、`TargetTracker` 和 HID 整数拆分函数。它在屏幕上生成一个目标，按实际的“固定中心准星、HID 移动使目标框反向移动”方式闭环运行，统计进入目标框需要几帧、多少毫秒。不需要模型、HDMI、OpenCV 或 HID 设备，也不会发送实际鼠标指令。

## 打开调参界面

```bash
make simulate PYTHON=/usr/bin/python3
```

本机浏览器打开 `http://127.0.0.1:8081/`。在板卡上运行、通过另一台电脑访问时：

```bash
make simulate PYTHON=/usr/bin/python3 SIM_ARGS="--host 0.0.0.0 --port 8081"
```

浏览器打开 `http://<板卡IP>:8081/`。此服务是独立的仿真工具，不需要启动 `yolo_app_26`，也不占用实机预览的 8080 端口。Ctrl+C 停止服务。

界面可修改控制参数、目标大小及位置、目标移动速度、时序和像素倍率；点击画面可设置目标初始位置。修改后点击“运行仿真”，用播放、慢放、上一帧／下一帧或进度条查看移动过程。可对比关闭预判的误差曲线，导出逐帧 CSV、含参数的 JSON，并复制实机控制参数。

## 默认参数与计数

默认画面 1920×1080，目标框 80×120，框中心在屏幕中心右侧 300 像素、垂直偏移 0；目标静止。身体瞄准点在框高度 20% 处，因此初始瞄准误差为 `(300, -36)`。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| 每帧耗时 | 20ms | 一帧检测／控制周期，50Hz |
| 额外反馈延迟 | 0ms | 从采集画面到该画面的控制结果可用，额外增加的固定延迟 |
| HID 报表间隔 | 1ms | 假定的 USB 可发送间隔，需按实际 USB 端点／主机测量 |
| Kp / Kd | 0.60 / 0.35 | 原有逐帧 PD 参数，没有积分项 |
| 鼠标倍率 | 0.5 | PD 输出到待发送 HID 单位的倍率 |
| HID 平滑系数 | 1.0 | 每份报表使用缓存的比例；每轴限制 ±127，整数化并保留余量 |
| X / Y 像素倍率 | 1 / 1 | 每个 HID 单位在源画面上造成多少像素的反向移动 |
| 预判提前量 | 0ms | 沿用现有跟踪器，可调 0–40ms |
| 连续入框帧数 | 5 | 判断连续入框所需的观测帧数 |
| 瞄准误差阈值 | 2px | 到真实瞄准点的二维距离阈值 |

帧 0 是目标刚出现、尚未发送控制移动的时刻。第 N 帧记录前 N 个周期结束的真实画面状态，时间为 `N × 每帧耗时`。同一时间边界先记录前一个周期，再处理新的检测和 HID 报表。启动释放按键的首份 HID 报表也占用一个报表时隙。

按这套默认假设，首次入框为 **7 帧 / 140ms**，从第 7 帧起连续 5 帧入框，达到真实瞄准点 2px 以内为 **17 帧 / 340ms**。这些数值针对上述目标位置、大小和倍率，不是所有场景的固定收敛时间。

统计项的解释：

- **首次入框**：真实目标框第一次覆盖中心准星的采样帧；初始就在框内时为 0。
- **连续入框**：第一次满足连续 K 帧入框时，这段连续区间的起始帧。至少观测到后续 K−1 帧才能确认；后续仍可能移出，需结合“移出次数”和全程曲线判断。
- **瞄准误差阈值**：第一次到真实瞄准点的距离小于等于设定阈值。入框与到达瞄准点是两个指标。
- **末段平均误差**：最后 25 帧的真实瞄准误差均值；不足 25 帧时使用全部已仿真帧，不含初始帧 0。
- **入框占比／移出次数**：全程帧末采样统计；不统计两个采样时刻之间短暂穿过框的情况。
- **虚拟点击**：展示原有自动点击判定及模拟报表中的按钮状态，只用于观察；“框外按下帧数”按帧末状态统计。

绿色框／点为当前真实目标，白色十字为固定准星；黄色点为最近一次处理的检测经过预判得到的瞄准点。加入反馈延迟后，黄色点可能来自较早的画面。

## 对照实机调优

先测像素倍率：让静止画面中的同一目标在输出已知 HID 位移后移动，使用 `画面反向位移像素 / HID 输出单位` 分别估算 X、Y 倍率。保持分辨率和电脑端灵敏度一致；关闭系统加速或在多个距离上重复标定。游戏内镜头移动的比例可能随视角、目标位置和灵敏度变化，本工具使用局部线性近似。

先在预判关闭、目标静止时调整 Kp、Kd、鼠标倍率和平滑。观察首次入框、连续入框和误差曲线，再加入测得的额外反馈延迟及 HID 报表间隔。最后加入目标速度，对照预判开／关。改变每帧耗时会改变每秒控制更新次数；Kd 沿用每帧误差差分，没有除以秒数。

当前预判基于屏幕相对速度，**未扣除自身 HID 移动造成的目标反向位移**，因此开启预判不一定更快。它还要求连续匹配至少 4 次，并把提前量限制在框对角线 25% 且最多 20px。大幅移动、小目标超出关联门限时，可能出现保留旧编号但暂停控制的短间隔；仿真保留这一行为，可通过跟踪编号、可见状态和误差平台段观察。

仿真暂时假设目标匀速、检测准确、USB 写入成功；画面内的检测框会按真实跟踪器逻辑裁边，离屏后视为不可见。尚未模拟漏检、检测噪声、USB 失败重试、帧间延迟抖动、鼠标加速和非线性视角变化。实际收敛时间需要在标定后对照验证。

界面复制的参数可以附到原有实机启动命令：

```bash
sudo ./yolo_app_26 --scores logits --target-classes 2,3 --head-classes 3 \
  --kp 0.6 --kd 0.35 --sensitivity 0.5 --deadzone 0 \
  --hid-smoothing 1 --prediction-ms 0 --aim-ratio 0.2
```

帧耗时、额外反馈延迟、HID 报表间隔、像素倍率和模拟目标参数只用于仿真。实机仍由实际采集、推理和 USB 时序驱动，不会为了模拟 20ms 而人为等待。

## 命令行与导出

```bash
make build/aim_simulator
./build/aim_simulator
./build/aim_simulator --help

# 目标向右匀速移动，额外延迟 20ms，预判 20ms
./build/aim_simulator --frame-ms 20 --feedback-ms 20 --vx 160 --prediction-ms 20

# 指定目标位置、大小与实测像素倍率
./build/aim_simulator --offset-x 450 --offset-y -80 --box-width 50 --box-height 90 \
  --gain-x 1.2 --gain-y 1.2 --kp 0.6 --kd 0.35

./build/aim_simulator --format csv > build/aim_trace.csv
./build/aim_simulator --format json > build/aim_result.json
```

CSV 每行包含帧号、时间、真实目标框、累计镜头位移、真实瞄准误差、最近处理的瞄准点与跟踪编号、PD 误差及输出、当帧 HID 整数位移和报表数、缓存余量、入框与虚拟点击状态。`move_x/y` 是最近一次控制更新的输出，`hid_dx/dy` 是当前帧内真正模拟发送的累计位移，两者在有延迟或缓存时可能不同。

JSON 同时保存参数、统计和完整轨迹；接口为 `GET /api/simulate`，参数名称与命令行一致（移除 `--`），`format=csv` 可下载 CSV。
